● Escrita (quando grava na memória vetorial)

  1. Mudança de arquivo no workspace — Graph.Watcher detecta arquivos
  modificados/criados (debounce de 3s), extrai o esqueleto do código via
  CodeSkeleton.extract, gera embedding via OpenRouter (bge-m3), e grava nó tipo
  "document" no PostgreSQL com pgvector.
  2. Consolidação de sessão — Archivist.consolidate extrai snippets semânticos
  da conversa via LLM, gera embedding de cada snippet, e grava nós com tipos
  variados ("learning", "bug", "fix", "decision", "person", etc.). Também extrai
   relações (edges) entre nós.
  3. Erros de ferramenta — Quando 3+ erros consecutivos no mesmo tool, o
  executor chama Storage.save_tool_error → grava nó tipo "tool_error".
  4. Lições do Kernel de Introspecção — Reflexões automáticas extraem lições que
   são persistidas via LessonStore (tabela lessons, sem embedding — são
  recuperadas por ID, não por similaridade).

  Leitura (quando recupera da memória vetorial)

  1. Toda rodada do executor — PromptAssembly.prepare → MemoryRecall.build é
  chamado antes de cada chamada ao LLM. Executa 4 buscas em paralelo:
    - Messages — full-text search no histórico de mensagens
    - Documents — full-text search nos documentos indexados
    - Semantic — embedding da query → busca por similaridade vetorial (cosine
  distance no pgvector)
    - Graph — busca no histórico do graph
  2. Elegibilidade — A busca semântica só dispara se a query tem 4+ palavras ou
  contém palavras-chave como "remember", "recall", "memory", "before",
  "previous", "bug", "deploy", etc.
  3. Resultado — Os hits ranqueados são injetados no system prompt como ### 
  MEMORY RECALL, junto com o conteúdo de USER.md e lições recentes.
